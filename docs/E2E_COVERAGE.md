# قائمة E2E الشاملة لتطبيق سرح — التغطية والنتائج

> اختبارات **فعلية** ضد المكدّس الحي: الـ API (NestJS) + لوحة الأدمن (Playwright) + ويب التطبيق (Playwright).
> التصنيف: **✅ مغطّى** = اختبار فعلي يمرّ · **N/A** = الميزة غير موجودة/غير مطلوبة أو تعتمد على منصة أصلية/بوابة خارجية · **FAIL** = ميزة موجودة ومطلوبة لكنها لا تعمل بشكل صحيح.

## كيفية التشغيل

```bash
# 1) أنشئ مستخدم أدمن للاختبار (مرة واحدة)
cd backend-nest && npm run ensure:e2e-admin

# 2) اختبارات API الحية (register/login/OTP dev، إعلانات، منشورات، دفع، ملاحم، دعم، صلاحيات، حواف)
cd backend-nest && npm run test:e2e:live      # 111 اختبار

# 3) لوحة الأدمن (متصفح حقيقي)
cd admin-panel && npm run test:e2e            # 11 اختبار

# 4) ويب التطبيق (متصفح حقيقي)
cd app && npm run test:e2e                    # 16 اختبار

# أو الكل دفعة واحدة
./scripts/run-live-e2e.sh
```

المتطلبات: الـ API على `:3001`، الأدمن على `:3000`، ويب التطبيق على `:8081`. وضع OTP التطويري يستخدم الرمز الثابت `123456`.

## 🐞 اكتشاف FAIL (تم إصلاحه)

**إنشاء تذكرة دعم كان يُسقط الخادم بالكامل.** الملف `support.controller.ts` كان يستورد الـ DTOs بـ `import type`، ما يحذف الأصناف وقت التشغيل فيتعطّل التحقق (ValidationPipe) تمامًا، ثم يصل جسم ناقص إلى `dto.subject.trim()` فيرمي `TypeError` غير معالَج **يُنهي عملية Node بالكامل** (ثغرة حجب خدمة يطلقها أي مستخدم).
الإصلاح: تحويل الاستيراد إلى `import { ... }` ليعمل التحقق. الآن الجسم الناقص → `400` والخادم يبقى حيًّا. مغطّى باختبار في `security-network-edge` و`butchers-support-services`.

### 14. 💳 الدفع + بوابة N-Genius الحقيقية — ✅ (سلك/منطق) / ⚠️ (المنفذ غير مُفعّل لدى المزوّد)
تم التحقق الفعلي من بوابة Network International (N-Genius) عبر التدفقات الثلاثة:

| المرحلة | النتيجة |
|---------|---------|
| الوصول للبوابة (TLS/DNS) | ✅ متاحة (200، ‎~0.45s) |
| المصادقة `access-token` (Basic + realm) | ✅ تُصدر توكن حقيقي (realm=NIARABIA) |
| إنشاء الطلب `create order` | ⚠️ **422 `inactiveOutlet`** — منفذ التاجر غير مُفعّل |

**الخلاصة:** الكود والتكامل سليمان، والاتصال والمصادقة يعملان، لكن **منفذ التاجر (`NI_OUTLET_ID`) غير مُفعّل** لدى Network International، لذا لا يمكن إنشاء أي عملية دفع حقيقية. الإصلاح **ليس في الكود** بل بتفعيل الـ Outlet (أو استخدام بيانات outlet مُفعّلة) من لوحة N-Genius.

**التدفقات الثلاثة المطلوبة — كلها مسلوكة للبوابة نفسها (`createNiCheckout`):**
- **صفحة الترويج/التعزيز** (`POST /api/listings/:id/boost` و`/promotion`): تصل للبوابة وتفشل حاليًا بـ 502 بسبب المنفذ غير المُفعّل. ✅ مسلوكة، بدون توكن→401.
- **سداد الرسوم** (`POST /api/payments/initiate` أنواع `fee`/`listing_fee`/`commission`): مرجع رسوم غير موجود→404 قبل أي محاولة شحن، والعمولة تصل للبوابة. ✅
- **الدفع بالملحمة** (`type: butcher_order`): مرجع طلب غير موجود→404 قبل الشحن (تحقق مطابقة المبلغ)، وسلك الدفع للبوابة نفسها. ✅

**إصلاح observability:** كانت صفحتا الترويج/التعزيز تُظهران رسالة مضلّلة "تعذر الاتصال ببوابة الدفع" (توحي بمشكلة اتصال بينما البوابة متاحة). تم تعديلهما لتُظهرا سبب البوابة الفعلي (مثل `inactiveOutlet`) عبر `formatNiGatewayError`، أسوة بمسار الدفع العام.

- **N/A في هذه البيئة**: حالات النجاح الفعلية (CAPTURED/PURCHASED) وحالات الرفض/الإلغاء وصفحة Return URL — تتطلب منفذ مُفعّل وبطاقة اختبار حية من N-Genius. الاختبارات تتحقق من السلك والأخطاء المنظّمة وتقبل النجاح تلقائيًا عند تفعيل المنفذ.
- مغطّى في `test/live/payment-gateway.e2e-spec.ts` (+ `payments-promote`).

## ملاحظات N/A (ميزات غير موجودة أو خارج نطاق E2E الآلي)

- **بث مباشر (broadcast)**: معطّل بعلم ميزة (`LIVE_BROADCAST_ENABLED=false`) — المشاهدة تعمل.
- **بوابة الدفع N-Genius**: طرف ثالث غير متاح من بيئة الاختبار؛ منطق التطبيق واختبار الأخطاء المنظّمة مغطّى.
- **الرسائل اللحظية / Socket.IO**، **Push**، **دورة حياة التطبيق الأصلية (background/rotation)**: تعتمد على منصة أصلية/اتصال socket ولم تُدرَج في هذه الجولة الآلية.
